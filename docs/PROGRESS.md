  - **Pool size chosen: `Maximum Pool Size` = 30 per instance.** *Why 30:* PostgreSQL's default `max_connections` is 100 and it keeps 3 for superusers, so ordinary clients share 97; the brief asked for room for 2 to 3 instances, and 3 x 30 = 90 fits while 3 x 40 = 120 does not, so 30 is the largest round value that fits three. It costs no throughput: a request holds one connection for one short transaction, the seat claim serialises on the class row anyway, and no code path takes a second connection while holding one (checked), so a full pool only makes requests queue (up to Npgsql's 15 s timeout), it cannot deadlock them. `max_connections` was **not** raised: it would not bound the client side and costs PostgreSQL memory; it stays the second lever (rule: `instances x pool size <= max_connections - 3`)
